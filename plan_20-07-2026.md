# ICONA — Optimization & Hardening Plan
**Date:** 2026-07-20
**Scope:** audit of the working tree + codebase, external research, ranked backlog.

---

## 0. Verdict up front

Two things outrank everything else on this list:

1. **Next.js 14.2 has been end-of-life since 2025-10-26.** No security patches for
   new CVEs. This app handles multi-tenant financial records.
2. **Tenant isolation is enforced on 14 of 48 Prisma models.** The other 34 —
   including `Transaction`, `Task`, `Subtask`, `TaskPhoto`, `Loan`, `JournalEntry` —
   are unscoped, and at least two API routes are confirmed exploitable today.

Everything else (performance, billing, DX) is real but secondary.

---

## 1. The uncommitted changes — verdict

Working tree: `.gitignore`, `README.md`, `src/lib/logger.ts` (new), `src/lib/prisma.ts`.

### `README.md` — keep as-is
Accurate rewrite from "marketing site" to "full SaaS app". Ship it.

### `src/lib/logger.ts` — needs a fix before commit
The intent (persist logs without touching ~78 existing `console.*` call sites) is
sound. Two problems:

| Problem | Why it matters | Fix |
|---|---|---|
| `fs.appendFileSync` on every `console.*` call | Blocking I/O on the request path. Every log line stalls the event loop for the whole process, not just that request. Under load this is the slowest thing in the app. | Swap to a single append `WriteStream` (`fs.createWriteStream(file, {flags:'a'})`), reused per day. One-line-ish change, non-blocking, no dependency. |
| `fs.mkdirSync` called on *every* line | Syscall per log line for a directory that exists after the first write. | Hoist out of `appendLine`; the stream creation path handles it once. |

Also worth deciding, not blocking:
- Monkey-patching `console` is legitimate here — it's the lazy way to capture 78
  existing call sites — but it means stack traces and log ordering can surprise you.
  Keep it; the alternative is editing 78 files.
- No rotation/cleanup. Daily files accumulate forever. One `unlink` sweep of files
  older than N days, run from the existing cron route, closes it.
- On Vercel the filesystem is read-only, so this silently no-ops (the `try/catch`
  handles it). That's correct behaviour, but it should be a documented `ponytail:`
  note, not a surprise.

**Research note:** [Pino](https://www.hirenodejs.com/blog/nodejs-pino-logging-production-2026)
is ~5x faster than the alternatives and uses a worker thread for transport. It is
the right answer *if* logs are ever shipped to Loki/ELK. It is not worth a
dependency today — a write stream gets 95% of the win for zero install. Revisit
when you have somewhere to ship logs to.

## 2. P0 — Security (confirmed, exploitable)

### 2.1 Cross-tenant IDOR: unscoped models
`src/lib/tenantPrisma.ts` `SCOPED_MODELS` lists 13 model names. The schema has 48
models, 14 of which carry an `orgId` column. So:

- Models **with** `orgId` but **not** in the list → silently unscoped.
- Models **without** `orgId` (`Transaction`, `Task`, `Subtask`, `Domain`,
  `TaskPhoto`, `Loan`, `Investment`, `JournalEntry`, `Measurement`,
  `ProjectDocument`, `WorkerWorkLog`, `Subcontractor*`, `SiteVisit`, `BoqRevision`)
  → cannot be scoped by the extension at all; they rely on each route
  hand-checking the parent project.

**Two confirmed live bugs where that hand-check is missing:**

```
src/app/api/transactions/[id]/route.ts:15-18
  Any ADMIN of ANY org can DELETE any transaction in the system by guessing/knowing its id.
  Looks up by bare `{ id: params.id }`, checks only `user.role === 'ADMIN'`, then deletes.

src/app/api/photos/[photoId]/route.ts:28-50
  Any ADMIN/MANAGER/EMPLOYEE of ANY org can archive any photo in the system.
  Same shape: bare id lookup, role-only gate, no org check.
```

~18 more routes use the same bare-id-lookup pattern on unscoped models and need
auditing individually.

**Fix strategy (ranked laziest-first):**

- **(a) Immediate, narrow:** patch the two confirmed routes by adding the org fence
  to the `where` (via the project relation). ~4 lines. Do this first, today.
- **(b) Structural, correct:** extend `SCOPED_MODELS` to cover every model that has
  an `orgId`, and add relation-based scoping for the child models
  (`where: { project: { orgId } }`). This is the todo's own "Strict Tenant
  Isolation" item and it's the one that actually closes the class of bug rather
  than the two instances.
- **(c) Belt and braces:** a test that, for each API route with an `[id]` param,
  asserts a request from org B for an org A resource returns 404. One table-driven
  test file, not one test per route.

Do (a) now, (b) as the main body of work, (c) alongside (b).

### 2.2 Next.js 14.2 is EOL
Per [Next.js support policy](https://nextjs.org/support-policy) and
[endoflife.date](https://endoflife.date/nextjs), v14 went EOL 2025-10-26; final
patch was 14.2.35 (the pinned version) on 2025-12-11.

- **Next.js 15** — Maintenance LTS, EOL **2026-10-21**. Three months of runway.
  Not worth the migration cost for a 3-month reprieve.
- **Next.js 16.2.x** — Active LTS. **Recommended target.**

Cost is not the version bump (`npx @next/codemod@latest upgrade latest` handles
most of it) — it's React 19 compat, async `params`/`searchParams` in route
handlers (this repo has 62 of them, many with `[id]` params), and NextAuth v4
compatibility. Budget a full day plus a smoke pass, not an afternoon.

### 2.3 Validation coverage
Zod is a dependency and is used in **12 of 62** API routes. The remaining 50 parse
request bodies untyped. Priority order: routes that write money (`transactions`,
`ledger`, `loans`, `investors`), then everything else.

## 3. P1 — Performance

### 3.1 `getServerSession()` runs on every Prisma query
`src/lib/tenantPrisma.ts:51` — when there's no `AsyncLocalStorage` override, the
extension calls `getServerSession(authOptions)` **per database operation**. Session
strategy is JWT (`src/lib/auth.ts:13`), so that's a cookie parse + JWT verify
(crypto) for every single query. A page doing 20 queries pays for 20 JWT verifies.

**Fix:** the machinery to avoid this already exists in the file —
`tenantLocalStorage`. Resolve `orgId` **once** per request in `getApiUser` /
a shared route wrapper, and run the handler inside `withTenantContext(orgId, ...)`.
The per-query `getServerSession` fallback then becomes a fail-closed error path
instead of the normal path. This matches the pattern the research consistently
recommends: [resolve tenant context once at the request boundary](https://vladimirsiedykh.com/blog/saas-architecture-patterns-nextjs).

This is the single highest-leverage performance change in the codebase.

### 3.2 Index coverage
13 `@@index([orgId...])` for 14 org-scoped models. Once (2.1b) lands and scoping
covers more models, every scoped query gains an `orgId` predicate — those need
composite indexes (`orgId` first, then the existing filter/sort column) or the
scoping change will *slow things down*. Indexing is not optional after 2.1b;
it's part of it.

### 3.3 `findUnique` → `findFirst` rewrite drops nested scoping
`src/lib/tenantPrisma.ts:84` re-dispatches to `baseClient[model].findFirst(...)` —
the *un-extended* client. The top-level `orgId` is injected manually so the direct
query is safe, but any nested `include` of a scoped model is not re-fenced.
Low severity, easy to miss, worth fixing while in the file.

### 3.4 Payload size
39 `findMany` calls in API routes, most without `select`. Fine at current scale;
flag it, don't fix it yet. Revisit when a tenant has real data volume.

## 4. P2 — Product / SaaS maturity

### 4.1 Billing provider
Stripe does not onboard Pakistan. Research on
[merchant-of-record platforms](https://fintechspecs.com/blog/stripe-vs-paddle-vs-lemon-squeezy-vs-polar-merchant-of-record-b2b-saas/):

| Option | Fit |
|---|---|
| **Paddle** | **Recommended.** MoR since 2012, handles global tax/VAT registration for you, native subscription lifecycle (trials, upgrades, downgrades, pauses) — which is exactly what `Organization.billingStatus` / `trialEndsAt` needs. Flat 5% + 50c. |
| Lemon Squeezy | Stripe-owned; aimed at solo devs / license keys. Add-on fees stack on international + subscription + PayPal, so the effective rate climbs above Paddle's for a global B2B SaaS. |
| Safepay | Local PK gateway. Useful *if* you want to bill Pakistani customers in PKR, but it is not a merchant of record — you'd own tax compliance. Consider as a second, local-currency rail later, not the primary. |

Work: one webhook route that flips `Organization.billingStatus`, plus checkout
links per tier. The plan-limit enforcement (`src/lib/entitlements.ts`) already exists
for projects.

### 4.2 Entitlements are half-wired
`entitlements.ts` gates project creation. Member limits (3/15/unlimited) are defined
but not enforced. Same helper, one more call site at the member-invite route.

### 4.3 Rate limiting is per-process
`src/lib/rateLimit.ts` uses an in-memory `Map`, correctly documented as
single-process-only. Fine on cPanel/VPS. **Becomes a real hole the moment you run
more than one instance** (Vercel, or PM2 cluster mode). Swap for Upstash Redis at
that point — not before.

### 4.4 `todo.md` is stale
Several items listed as pending are already shipped:
- "Security Headers & Session Hardening" — CSP, HSTS, `X-Frame-Options: DENY`,
  Referrer-Policy, Permissions-Policy all present in `next.config.mjs`.

And the deploy section says Vercel while `next.config.mjs` sets
`output: 'standalone'` and the README documents a cPanel/VPS target. Pick one; it
changes the answers for logging (§1), rate limiting (§4.3), and file storage.

## 5. Proposed sequence

**Phase 1 — stop the bleeding (do first, small diffs)**
1. Fix `logger.ts` write stream + mkdir hoist. Commit the working tree.
2. Patch the two confirmed IDOR routes (`transactions/[id]`, `photos/[photoId]`).
3. Rewrite `todo.md` against reality.

**Phase 2 — close the bug class**
4. Audit the ~18 remaining bare-id routes on unscoped models.
5. Extend `tenantPrisma` scoping to all org-owned + project-owned models.
6. Add the composite `orgId` indexes that step 5 requires.
7. One table-driven cross-tenant access test.

**Phase 3 — performance**
8. Resolve `orgId` once per request; make the per-query `getServerSession` a
   fail-closed path.

**Phase 4 — supported framework**
9. Next.js 16 upgrade + React 19 + async params codemod + smoke pass.

**Phase 5 — revenue**
10. Paddle checkout + webhook → `billingStatus`.
11. Member-limit enforcement.

**Deferred (documented, not done)**
- Pino / structured logging — when there's a log sink to ship to.
- Upstash rate limiting — when there's more than one instance.
- Turnstile, MFA, breached-password screening — after Phase 2. Bot defense on an
  app with an open IDOR is putting a lock on an open window.
